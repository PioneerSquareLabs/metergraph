# SDK 0.4+ Self-Hosted Ingestion and Demo Design

## Problem

The self-hosted quickstart currently proves only a legacy direct HTTP path:
`scripts/seed_demo.py` constructs a schema-v1 batch and sends an app token to
`POST /v1/ingest`. MeterGraph SDK 0.4 and later use repository-aware ingestion
when repository metadata is available. They first exchange the app token at
`POST /v1/ingest/sessions`, then send batches to `POST /v1/ingest` with the
short-lived session token. The OSS server does not implement that exchange, so
the advertised demo can succeed while the current SDK fails to deliver.

Externally, this capability will be called **SDK 0.4+ ingestion**. The existing
`protocol_version: 2` wire value remains unchanged for compatibility, and
protocol-level tests may use “v2” where that precisely describes the assertion.

## Goals

- Make the OSS server compatible with repository-aware ingestion in SDK 0.4+.
- Preserve direct app-token ingestion for older SDKs and existing integrations.
- Make the no-provider-key demo exercise the published Python SDK itself.
- Remove “protocol v2” terminology from customer-facing docs, errors, comments,
  and demo output.
- Add tests that prove session exchange, expiry, tamper rejection, legacy auth,
  and the SDK-driven demo path.

## Server Contract

`POST /v1/ingest/sessions` requires an app token from `MG_TOKENS` and accepts:

```json
{
  "protocol_version": 2,
  "repository": "github.com/example/project",
  "sdk_version": "0.4.0"
}
```

The server validates bounded, non-empty string fields and the supported wire
value, then returns:

```json
{
  "session_token": "mgs1.…",
  "expires_at": "2026-08-17T12:05:00Z"
}
```

Session tokens are short-lived, stateless, URL-safe HMAC-signed envelopes. The
signed payload contains an expiry and repository identifier; it contains no app
token. Signing and verification derive from the matching configured app token,
so tokens work across multiple server workers without a new database table or
shared in-memory state. Default lifetime is five minutes and may be configured
with a bounded `MG_SESSION_TTL_SECONDS` value.

`POST /v1/ingest` accepts either a configured app token (backward compatibility)
or a valid, unexpired session token. Other authenticated dashboard/API routes
continue accepting app tokens only. Invalid, expired, and tampered session
tokens return the existing generic `401 invalid token` response.

## Demo

`scripts/seed_demo.py` will import the published `metergraph` Python package,
initialize it against `MG_URL` with `MG_TOKEN`, wrap a local OpenAI-shaped fake
client, and invoke that client inside representative MeterGraph route and trace
contexts. The fake returns realistic response metadata and usage but performs no
network provider call, so the demo remains free of provider API keys.

The script will flush and shut down the SDK in a `finally` block and fail with a
clear installation instruction when the package is missing. Because it runs in
the cloned Git repository, normal SDK 0.4+ repository discovery triggers the
session exchange before batch ingestion. The demo no longer constructs or posts
wire payloads itself.

Historical backdating is intentionally removed: SDK capture timestamps describe
real instrumented calls. The demo can create enough current calls to populate
the overview while truthfully exercising the production SDK path.

## Documentation and Terminology

The README and self-hosting guide will:

- install `metergraph>=0.4` before running the demo;
- describe session exchange as “SDK 0.4+ ingestion”;
- document `/v1/ingest/sessions` and session-token acceptance on `/v1/ingest`;
- state that app-token direct ingestion remains supported for older clients;
- document `MG_SESSION_TTL_SECONDS`;
- avoid public “protocol v2” naming while preserving the wire field.

## Verification

- Unit tests cover session-token issue/verify, expiry, tampering, malformed input,
  and retention of app-token authentication.
- API integration tests exchange a token and ingest with it.
- A demo test runs the script against a local test server with the real installed
  SDK and asserts that `/v1/ingest/sessions` precedes `/v1/ingest`.
- Existing server tests and dashboard checks continue to pass.
