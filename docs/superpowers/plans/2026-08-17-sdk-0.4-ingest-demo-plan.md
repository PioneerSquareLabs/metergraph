# SDK 0.4+ Self-Hosted Ingestion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make MeterGraph OSS accept the session-based ingestion used by SDK 0.4+ and make its quickstart demo exercise the real Python SDK rather than a handcrafted HTTP payload.

**Architecture:** A focused `sessions.py` module issues and verifies stateless, five-minute HMAC session tokens derived from configured app tokens. The session route requires an app token, while ingest accepts either legacy app tokens or valid session tokens. The demo wraps an in-process OpenAI-shaped fake client with the published SDK, producing genuine captured batches without a provider API key.

**Tech Stack:** Python 3.10+, FastAPI, stdlib HMAC/base64/JSON, pytest, MeterGraph Python SDK 0.4+

## Global Constraints

- Customer-facing terminology is “SDK 0.4+ ingestion,” never “protocol v2.”
- Preserve the wire field `protocol_version: 2` for SDK compatibility.
- Protocol-level tests may use “v2” when it precisely describes the assertion.
- Preserve direct app-token authentication on `/v1/ingest` for older SDKs and integrations.
- Do not require provider credentials or make provider network calls in the demo.
- Session tokens must be stateless, short-lived, URL-safe, and contain no app token.
